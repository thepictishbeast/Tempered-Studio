- `31b-futures-are-lazy` — **Lesson 31b — Futures are lazy: why async needs a runtime** — The core async rule that a future does nothing until driven, which is why async code needs a runtime and why .await is restricted and main cannot be async on its own.
- `32b-encapsulation` — **Lesson 32b — Encapsulation: private fields, public methods** — How keeping struct fields private and exposing only public methods enforces invariants in one place and lets you change internals without breaking callers.
- `32c-states-as-types` — **Lesson 32c — States as types: broken states won't compile** — How giving each stage its own type (e.g. DraftPost vs PublishedPost) makes wrong-state operations unrepresentable, with transitions that consume self to retire the old state.
- `33-refutability` — **Lesson 33 — Refutability: when a pattern can fail** — The refutability rule that governs where patterns may sit: irrefutable patterns (always match) are needed for let/for/params, while refutable ones (can fail) require an else path via if let/while let/match.
- `33b-guards-bindings-nested` — **Lesson 33b — Guards, `@` bindings & nested patterns** — Three pattern power tools for match: match guards add a value condition to an arm, @ bindings capture a value while range-testing it, and nested destructuring reaches into layered data.
